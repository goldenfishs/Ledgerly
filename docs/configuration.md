# 配置说明

Ledgerly 的日常管理通过页面完成；端口、数据目录、反向代理和可选发票识别由部署环境配置。

## 系统设置

系统管理员可进入「系统设置」修改系统名称、注册方式和邮件服务。账本管理员的权限只作用于已加入的账本，不能修改系统配置。

系统名称用于侧栏、页面标题与公开账号页面。账本名称在「我的账本」或「账本设置」中单独修改。

### 注册方式

| 方式 | 新账号 | 已有账号 |
| --- | --- | --- |
| 仅邀请注册（默认） | 通过有效账本邀请链接注册并加入账本 | 可登录并接受邀请 |
| 开放注册 | 可从登录页注册，之后通过邀请加入账本 | 可登录并接受邀请 |
| 关闭注册 | 公开注册与邀请注册都关闭 | 可登录并接受邀请 |

开放注册创建的账号默认是普通用户，没有系统管理权限或账本成员资格。修改注册方式不会删除已有用户或改变账本权限。

开启「注册时必须验证邮箱」后，公开注册和邀请注册都要求邮箱验证码。关闭时，新用户可以不填写邮箱；填写的邮箱仍需通过验证码验证。已有账号不会因为开启此选项而被强制退出。

### 邀请

- 在目标账本的「账本成员」生成邀请，选择成员或管理员角色。
- 链接只在创建时提供，默认有效期 7 天，最长 30 天，每条仅供一个账号使用。
- 未使用的邀请可以撤销。邀请人的管理员资格被移除、停用或降级后，其未使用邀请失效。
- 已有启用成员再次接受邀请时保留原角色；调整角色应使用成员管理。
- 每个账本至少保留一位启用管理员。

邀请链接使用当前访问地址。多人协作前应先使用团队共同可访问的地址登录，再生成链接。

## SMTP 邮件服务

SMTP 配置保存在系统数据库中，不需要填写 `.env`。邮件服务用于注册验证、个人邮箱绑定、密码找回及手动发送测试邮件。

在「系统设置 → 邮件发送服务」填写：

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 服务商提供的域名或 IP 地址，不包含 `https://` 等协议前缀 |
| 端口与连接安全 | 按服务商参数选择 STARTTLS、SSL / TLS 或无加密连接 |
| SMTP 登录账号 | 邮箱地址或服务商指定账号；本机无认证测试服务可留空 |
| 密码或邮箱授权码 | 按服务商要求填写授权码或密码，保存后不会回显 |
| 发件人邮箱与名称 | 收件人看到的发件信息，邮箱应符合服务商的发送要求 |

启用并保存后，手动填写测试收件邮箱，点击「发送测试邮件」。该按钮只使用已保存的配置；保存配置不会自动发送邮件。

编辑配置时，密码留空表示保留已保存值；勾选「清除已保存的授权码」才会移除旧值。无加密连接可用于本机 SMTP 测试，外部邮件服务应按服务商提供的加密方式连接。

确认邮件能够收到后，再开启强制邮箱验证。强制验证开启时，系统会阻止直接停用 SMTP；需要先关闭验证要求。

验证码有效期为 10 分钟，单次使用，重新发送至少间隔 60 秒。系统还限制每个邮箱与来源的请求频率。验证码按邮箱、用途和账号或邀请绑定，注册验证码不能用于重置密码。SMTP 发送失败时，该验证码不会生效。

找回密码的发码请求返回通用提示，不公开邮箱是否关联账号。找回功能只能用于已经绑定并验证的邮箱。未配置邮件服务时，仍可采用不填写邮箱的注册流程，前提是系统未要求强制邮箱验证。

SMTP 授权码加密保存在数据库中，密钥位于数据目录的 `system.key`。迁移和备份必须保留该文件；系统不会通过配置接口返回密钥或已保存的授权码。

## 个人中心

用户点击个人信息进入个人中心，即使未加入账本也可以使用：

- 修改显示名称和登录账号。账号使用 3–40 位字母、数字、点、下划线或短横线，必须唯一；更改账号需要当前密码。
- 修改密码时验证当前密码，新密码至少 8 位。成功后当前浏览器获得新会话，其他旧会话失效。
- 上传不超过 2 MB 的静态 JPG、PNG 或 WebP 头像，也可以移除头像。图片会裁为方形并重新编码，原图元数据不保留。
- 使用当前密码和邮箱验证码绑定邮箱。完成验证后，可用账号或该邮箱登录，也可通过邮箱找回密码。

密码找回入口在登录页。重置密码成功后，该账号的全部旧会话失效，需要重新登录。

## 环境变量

Compose 会读取仓库根目录的 `.env`。完整示例见 [`.env.example`](../.env.example)。`STUDIO_` 前缀用于保持配置与既有数据兼容，不代表需要其他服务。

| 变量 | 默认值或作用 |
| --- | --- |
| `LEDGERLY_BIND_HOST` | Compose 对外绑定地址，默认 `127.0.0.1` |
| `LEDGERLY_PORT` | 宿主机端口，默认 `10670` |
| `LEDGERLY_IMAGE_TAG` | Compose 构建及使用的本地镜像标签，默认 `local` |
| `LEDGERLY_API_PROXY` | 本地 Vite 开发代理，默认 `http://127.0.0.1:8000`，在启动 npm 的进程环境中设置 |
| `STUDIO_PUBLIC_ORIGIN` | 公开访问的协议、域名及可选端口；直连时可留空，HTTPS 反向代理时填写实际来源 |
| `STUDIO_COOKIE_SECURE` | HTTPS 部署设为 `true`，要求浏览器通过安全连接发送登录 Cookie |
| `STUDIO_DATA_DIR` | 后端数据目录；容器固定使用 `/app/data`，直接运行默认使用仓库的 `data/` |
| `STUDIO_WEB_DIR` | 后端提供的前端文件目录；容器为 `/app/web`，直接运行默认为 `frontend/dist/` |
| `STUDIO_LLM_API_KEY` | 可选图片识别服务的 API Key |
| `STUDIO_LLM_BASE_URL` | 可选兼容接口基础地址，例如服务商提供的 `/v1` 地址 |
| `STUDIO_LLM_MODEL` | 可选识别模型名称，模型需要支持图片输入 |
| `STUDIO_LLM_CONFIG_PATH` | 可选 INI 配置文件路径，仅在显式提供文件时使用 |
| `STUDIO_BUILD_DIR` | 前端构建输出目录，默认 `frontend/dist/`；供本机构建或验证使用 |
| `NODE_BASE_IMAGE` | Docker 前端构建基础镜像，默认 `node:22-alpine` |
| `PYTHON_BASE_IMAGE` | Docker 后端运行基础镜像，默认 `python:3.12-slim` |

`STUDIO_DATA_DIR`、`STUDIO_WEB_DIR` 和 `STUDIO_BUILD_DIR` 是对应进程的环境变量。修改 `.env` 中未在 Compose 引用的变量不会自动改变容器设置；需要在自己的 Compose 配置中明确传入。本地 Vite 不会自动读取 Compose 的 `.env` 来设置代理，可显式运行 `LEDGERLY_API_PROXY=http://127.0.0.1:8001 npm run dev --prefix frontend`。

### 可选发票 AI 识别

填写 `STUDIO_LLM_API_KEY`、`STUDIO_LLM_BASE_URL` 和 `STUDIO_LLM_MODEL` 后重新创建服务：

```sh
docker compose up -d
```

后端向基础地址后追加 `/chat/completions`，采用带图片输入的兼容 Chat Completions 请求。基础地址不应再包含该接口路径。图片或 PDF 第一页会发送给你配置的服务商；API Key 只在后端使用。

识别支持 JPG、PNG、WebP 和 PDF，每个原件不超过 15 MB。PDF 原件完整保留，预览和识别使用第一页。识别失败仍会保留文件，可以重试或手工填写；未知金额不会被自动补为零。

不使用环境变量时，也可通过 `STUDIO_LLM_CONFIG_PATH` 指向 INI 文件。支持 `[ledgerly]` 节及兼容的 `[easy-accounts]` 节，字段为 `api_key`、`url`、`model`；同名环境变量优先。文件需要通过只读挂载或其他方式实际提供给容器，系统不会查找外部项目目录。
